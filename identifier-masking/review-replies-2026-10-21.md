## Thread 1: jjmata, app/models/identifier_mask.rb:61 (`mask_identifiers`): "over-masking cascade ... `"brand" => "•••visa"`"

Resolve after posting: yes

Reply:

Good catch, thanks. Fixed in 0e0c695de and a925a76f5. Inside an object stored under an identifier key, descriptive fields (`name`, `brand`, `type`, `currency`, `last4`, ...) now stay readable, and every other value is still masked at any depth. So `{"card_number" => {"last4" => "1234", "brand" => "visa"}}` keeps `"visa"`, `{"counter_account" => {"name" => "Jane Doe", "number" => "1234567890/2010"}}` keeps the name and masks the number to `•••7890/2010`, and a number under an unexpected key such as `accountId` or one level deeper is still masked. I kept masking as the default rather than listing the number keys, so a payload shape we haven't seen can't leak the full value. Regression tests cover both directions.
