## Thread: coderabbitai, set_transaction_merchant.rb lines 37-38 (unlink can commit between the eligibility check and the target load)
Not changed. The window is a single rule run racing an unlink in the same instant, and the outcome is that one batch of transactions gets the provider merchant the user just unlinked. That shows up in the list and can be undone, and the next run skips it because the merchant is no longer assignable. Taking the runner's advisory lock in `unlink_from_family` would make a plain UI action wait behind long rule runs, which seems the worse tradeoff. Happy to add it if you see it differently.
