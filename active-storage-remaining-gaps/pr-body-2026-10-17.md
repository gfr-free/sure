## Summary

Before: Receipt files on transactions were served through blob URLs to every member of the family, including members the account was not shared with. Tracked variants and PDF previews are separate blobs with their own record types, so thumbnails of receipts and statements were served to any signed-in user who had the link. Archived-export downloads and API export downloads redirected to the session-only blob routes. The archive token holder, whose account is gone, and API-key clients both ended up on the login page. Meanwhile, archive files and family export files could be read by any signed-in user who had the blob link, and a signed disk URL kept serving a file after its blob row was gone.

After: Receipt files follow account sharing, the same rule `TransactionAttachmentsController#set_transaction` uses. Variants and previews are authorized through the blob they were made from. Archived-export and API export downloads send the file themselves after their own token or API-key check, and the blob routes no longer serve archived exports. Family export files are served only to admins of the export's family, and a disk key without a blob row returns 404.

This complements #4203, which covers export, import and document blobs. Both PRs check family exports. An earlier revision of this PR added `FamilyExport` to `PROTECTED_RECORD_TYPES` too, so it conflicted with #4203. This PR now uses a separate guard instead, so it merges cleanly with #4203 and with `main` in either order. I checked this with `git merge-tree` and by running the access tests on the merged result. Once both PRs are in, the family export check runs twice with the same rule. I'll drop the guard here in a follow-up.

## How

- `transaction_attachment_authorized?` also requires `account.shared_with?(Current.user)`, not just the family.
- `attachments_with_sources` replaces `ActiveStorage::VariantRecord` and `preview_image` attachments with the attachments of their source blob. It follows at most two steps (a variant of a preview), and a missing source fails closed.
- `ArchivedExportsController#show` and `Api::V1::FamilyExportsController#download` stream the blob with `ActiveStorage::Streaming#send_blob_stream`. `ArchivedExport` attachments return 404 on the blob, representation and disk routes. A file missing from storage returns 404.
- `FamilyExport` attachments go through their own guard next to the `ArchivedExport` one, which releases them only to admins of the export's family. It mirrors `FamilyExportsController`.
- `disk_service_blob` uses `find_by!`, so a validly signed disk key whose blob row was deleted, for example between a purge and its file deletion, returns 404 instead of skipping the checks.
- API: `download` now returns 200 with the zip instead of a 302 to a route that API keys cannot use. The rswag spec documents it as `application/zip` binary and `docs/api/openapi.yaml` is regenerated.

| Disk service | checked | checked | 404 | n/a |
| Token download | n/a | n/a | token check, file sent | n/a |
