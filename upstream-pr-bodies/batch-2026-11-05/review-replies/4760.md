## Thread: coderabbitai, market_data_reset_job.rb line 10 (unique lock doesn't dedupe ActiveJob submissions)
Right, the ActiveJob wrapper carries a new job id each time. Fixed in 2868bd161: the controller now calls `MarketDataResetJob.enqueue_once`. It writes a cache key with `unless_exist` (Redis in production) and only then enqueues; the job deletes the key when it ends. A second click while a reset is queued or running gets "A market data reset is already queued or running." The job also takes a Postgres advisory lock, so two resets that were queued anyway never run at the same time. Tests: "enqueue_once queues one reset until it has run" and the controller test for the second click.

## Thread: coderabbitai, market_data_reset_job.rb lines 16-17 (deletes dates outside the import windows)
Fixed in 2868bd161: the job deletes per security only the dates in `MarketDataImporter#required_security_price_windows`, and per currency pair only the dates from `#required_exchange_rate_pairs` up to the importer's end date.
