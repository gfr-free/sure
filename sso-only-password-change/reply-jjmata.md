Thanks for catching this, you're right that the admin path contradicted the stated policy. Fixed in 5fbc856.

`Admin::UsersController#update` now applies the same rule as the password page and local sign-in (`AuthConfig.local_login_allowed_for?`):

- When local login is disabled, an admin can no longer set a password for a user who could not use it to sign in. The request is rejected with an alert and nothing else from that submission is saved (a role change in the same form is not applied either).
- Under the local admin override, passwords can still be set for super admins, since the override is exactly what lets them sign in with a password. Regular users stay blocked.
- The "Set new password" field on the admin users page is hidden whenever the password could not be saved, so the form no longer offers it.
- Role-only changes without a password keep working in SSO-only mode.

Tests in `test/controllers/admin/users_controller_test.rb` cover SSO-only rejection, role-only updates, the override for regular users vs. super admins, and the hidden field. The new alert is translated in every locale that already has the admin update messages.
